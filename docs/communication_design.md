# 树莓派 ↔ DJI C 板通信设计草案

状态：下文为未来运动控制草案，不用于当前视觉协议。当前 Pi 视觉 UART V1 已实施，
以 [uart_v1.md](uart_v1.md) 的 1 字节 LENGTH 和消息类型为准。固件V1已完成软件接入，硬件联调待验；以下运动控制草案仍不执行。

## 层级职责
树莓派：视觉、二维码解析、全场定位、路径规划、速度指令生成。
DJI C 板：电机实时控制、CAN、状态反馈、超时停止。

## 物理链路
建议评估 USART3，实际需核实接口、3.3V TTL、电源地与树莓派系统串口配置。USART1 已用于 CRSF。

## 建议二进制帧
SOF(2) | version(1) | type(1) | seq(2) | payload_len(2) | payload | CRC16(2)

端序、数值类型、CRC 参数及坐标单位需在实现前定稿。

消息建议：HELLO / HEARTBEAT / SET_VELOCITY / STATUS / STOP / ACTUATOR_COMMAND。
自主与遥控控制权由单点仲裁，不能双任务并行写底盘目标速度。
命令超时建议初始验证值 200ms，最终以实际延迟与安全停车实验确定。

最小验证：帧解析 → 虚拟串口 → 树莓派实物握手 → 低速执行与反馈 → 断线停车。
