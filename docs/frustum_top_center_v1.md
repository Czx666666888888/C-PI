# 圆台上表面中心实验 V1

独立分支 `feature/frustum-top-center`，基于 `feature/stm32-uart-v1` 的 `9f967ca`。工具入口为 `PI/vision/experiments/frustum_top_center.py`，所有实验筛选参数在同名JSON；初始数值是待标定的实验假设，不是已验证的通用阈值。未替换生产算法、改参考点、通信或固件。

## 几何与方法

整体颜色连通域包括上表面和侧面。外接矩形中心由轮廓极值决定，侧面改变极值便会偏移；面积质心同样被侧面面积加权。两者只作为对照，不能解释为抓取中心。

复用 `legacy.physical_detect.colors_to_track`（含红色双HSV区间），按原处理顺序执行红通道0.9、5×5高斯、HSV阈值和5×5开运算。实验在干净图像上分割，不复制原程序分割前画参考十字的副作用。最大外轮廓与原500像素面积阈值用于整体ROI和矩形/质心对照，不送入上表面fitEllipse。

- A_gradient：V通道Sobel局部梯度、Canny、ROI内部约束；由内部边缘轮廓以及随机5点生成候选，用全体内部边缘的近似几何距离筛内点，再fitEllipse细化。支持部分边缘，但纹理/阴影也可能形成错误候选。
- B_contour：灰度高斯+Canny，在侵蚀后的ROI中寻找内部轮廓，逐个拟合和细化。覆盖角度筛选约束近闭合程度，断裂严重时预期报INVALID。
- 两方法共用中心在ROI内、顶部位置先验、轴比、相对宽度/面积、最少支持点、角度覆盖率及残差筛选。参数均可调，但不可为追求成功率而逐帧调阈值。当前顶部先验假设上表面位于图像ROI的较上部分；相机翻转/圆台倒放等不符合该先验。
- 实物检查发现A可能拟合侧面短弧。因此A/B只标作候选，最终TopEllipse要求两方法均通过且中心距离不超过配置agreement_px（初始3像素，仍待标注校准），选取残差较低的已有椭圆，不平均成一个未经拟合的中心；否则最终FitValid=False。两方法相关，并非独立测量，一致性也不能保证绝对正确。
- `residual_px` 为隐式椭圆的一阶几何距离近似的内点RMS，不是精确最近点距离；`coverage`为24角度分箱的支持比例。FitValid只表示通过这些数值筛选，仍须人工确认边缘确实是上表面；低残差不保证语义正确。
- 上表面不可见、反光、弱对比、遮挡、ROI过小等均可能失败。侵蚀会排除侧面外边界，也会删去与外轮廓重合的上表面后沿；应通过剩余内部弧的支持判断，不把整个颜色轮廓当圆。

OpenCV接口依据：[fitEllipse/轮廓特征](https://docs.opencv.org/4.13.0/dd/d49/tutorial_py_contour_features.html)。图像椭圆中心仅是二维估计，透视下不等于真实三维圆心投影；未标注时不能报告绝对定位精度。

## 使用与输出

先检查 `systemctl is-active cpi-vision`、`fuser /dev/video0`。服务占用摄像头时按既有流程征得用户确认，再临时停止；退出、检查无实验采集占用后恢复原服务。工具不会自行停止服务，也不打开任何控制串口。

```powershell
python PI/vision/experiments/frustum_top_center.py --help
python PI/vision/experiments/frustum_top_center.py --host cpi --duration 15 --label center --output .local/frustum-center-still
python PI/vision/experiments/frustum_top_center.py --image .local/example.jpg --headless --output .local/frustum-offline
python -m unittest discover -s PI/tests -v
```

沿用OpenSSH配置/免密密钥和严格主机验证。Pi仅采集640×480 MJPG，再以长度前缀JPEG（质量95）传Windows；Windows进行两种实验分析并显示四格画面。队列只保留最新帧，主动跳过的预览帧单独计数，不当作摄像头丢帧；JPEG压缩会影响边缘，后续应比较无损样本。处理时间较长时算法FPS不等于摄像头采集FPS。

画面显示原图、HSV Mask、外轮廓/矩形、矩形中心（黄）、质心（青）、A候选椭圆中心（紫）、B候选椭圆中心（绿）、最终TopEllipse（橙）、两套候选边缘以及白色参考点(290,260)。失败显示INVALID，不回退成矩形中心。Q/Esc/关闭窗口退出；1/2/3/4/5切换中央/左/右/上/下标签。静止指标应单独开15秒会话或排除移动阶段，不能把移动过程算抖动。

终端逐方法报告cx/cy/dx/dy、FitResidual、最终FitValid及CandidateValid。统一 `dx=cx-290`、`dy=260-cy`，不再减参考点。每帧CSV保存两种基线、A/B候选及最终TopEllipse；summary.json按位置和方法统计数值通过率、中心标准差、连续有效相邻帧位移RMS、与矩形中心均值差。INVALID占分母；连续帧位移不会跨越INVALID帧计算。无有效拟合时输出null，而不是0误差。移动标签间的中心均值变化是物体位置变化，不是定位误差。

结果目录另保存配置快照、最近原图及对比图，全部放忽略的`.local/`，不提交照片、CSV或运行日志。不要对未经确认静止的片段宣称抖动指标，不对无真值样本宣称精度。需用人工标注的上表面边界/中心，再比较各位置相对标注的偏差。

### 结论与下一阶段

目前不建议替换生产模块。A能在部分视角拟合候选，但更抖且会选错边缘；B在当前小目标/弱内部边缘下缺少覆盖，全部固定位置失败。最终保守输出INVALID是诚实拒绝，不代表已经解决中心定位。

优先顺序：先固定相机姿态/焦距并增大物块成像尺寸、用可控漫射光减少侧面高光，确认原始图中上表面边界可辨；采同一物体五位置与光照下的无损样本并人工标注边界/二维中心；再依据标注验证边缘方向、外轮廓重合的上缘与内部前弧的组合、局部颜色/梯度一致性和鲁棒拟合。当前ROI顶部位置先验未标定，跨画面位置时上表面可能出现在不同方向，需一并验证，不能仅靠图像y较小选择“顶部”。最后才考虑时间滤波；滤波不能修复抓错平面或固定偏差。镜头畸变、透视椭圆中心与三维圆心投影差异仍是独立误差来源；绝对定位精度UNVERIFIED。
